## 0. PRD 总览

### 0.1 背景与目标

本期需求围绕学情报告二期能力升级，目标是让家长更容易理解孩子真实学习情况，并通过报告内容带动推荐应用、学习计划和学情分享的使用。

核心目标:

- **提升有效报告查看率:** 根据孩子真实学习情况提供有针对性的报告内容。学得多的孩子突出重点、进步和薄弱点；学得少的孩子也提供可执行的学习建议。
- **提升推荐应用/学习计划使用率:** 通过学习成果、学习建议和推荐卡片，让家长理解自研应用优势及适用场景。
- **提升学情内容分享率:** 通过学情分享功能，让家长展示孩子学习成果，形成口碑传播。

### 0.2 需求来源

## 2. M1 学情报告基础与学情总结

### 2.1 模块目标

在日报/周报详情页提供"学情总结"能力，用简洁的总结文案、表现标签、学习时长和应用使用情况帮助家长理解孩子当前阶段的学习表现。

### 2.2 适用范围

| 项 | 说明 |
| --- | --- |
| 适用版本 | App 版本 ≥ V4.0.0 |

| 报告范围 | 日报、周报 |
| 入口 | 学习 tab 页点击【日报周报】进入报告页；点击学情报告消息进入报告页 |

### 2.3 展示与生成规则

| 场景 | 规则 |

| 🆕 数据延迟兜底 | 若报告生成时数据未就绪（如数据管道延迟），展示"报告生成中"加载态，最长等待 30 分钟后展示已有数据 |

> **学习机消息文案设计原则:**
> - **首次鼓励（一次性奖励）：** 当孩子首次收到家长的任何鼓励，固定下发 5 颗星星币，专属通知文案为：“已为你送上 5 颗星星币！快来瞧瞧爸爸/妈妈给你的鼓励吧～”
> - **常规鼓励（无星星币）：** 自第二次收到鼓励起，不再发放星星币，下发常规消息通知，规则如下：
>     - **高分段（≥55分）:** 点明具体鼓励动作（击掌/点赞/拥抱/夸奖），制造惊喜感和成就感（不含星星币文案）
>     - **中分段（35-54分）:** 以"加油"为主基调，保持正向激励（不含星星币文案）
>     - **低分段（<35分）:** 不提星星币，不暴露评分结果，使用"有话想对你说"的温和表达，避免孩子在通知栏就感到压力
> - **"爸爸/妈妈":** 根据发送鼓励的家长身份动态替换。⚠️ 如无法获取家长身份，使用"爸爸妈妈"

### 2.4.1 🆕 综合评分计算公式

**评分维度与权重:**

| 维度 | 权重 | 评分依据 | 分值范围 |
| --- | --- | --- | --- |
| 使用时长变化 | 25% | 本周/当日使用时长长达5分钟，相对上周/昨日的变化幅度 | 0-100分 |
| 刷练知识点变化 | 25% | 本周/当日使用时长长达5分钟，相对上周/昨日的变化幅度 | 0-100分 |
| 答题正确率变化 | 15% | 本周/当日使用时长长达5分钟，相对上周/昨日的变化幅度 | 0-100分 |
| 习题数量变化 | 15% | 本周/当日使用时长长达5分钟，相对上周/昨日的变化幅度 | 0-100分 |
| 观看课程数量变化 | 10% | 本周/当日使用时长长达5分钟，相对上周/昨日的变化幅度 | 0-100分 |
| 学习目标完成率 | 10% | 目标完成百分比 | 0-100分 |

**综合评分公式:**

```
综合评分 = (时长变化得分 × 0.25) + (刷练知识点变化得分 × 0.25) + 
          (答题正确率变化得分 × 0.15) + (习题数量变化得分 × 0.15) + 
          (观看课程数量变化得分 × 0.1) + (目标完成得分 × 0.1)
```

**各维度评分细则（以周报为例）:**

| 维度 | 变化幅度 | 得分 | 示例 |
| --- | --- | --- | --- |
| 使用时长变化 | 增加 50%+ | 100分 | 本周时长: 5小时（上周3小时）→ 增加 67%，得分100 |
| 使用时长变化 | 增加 0-50% | 85分 | — |
| 使用时长变化 | 持平 | 70分 | — |
| 使用时长变化 | 减少 0-30% | 60分 | — |
| 使用时长变化 | 减少 30%-50% | 40分 | — |
| 使用时长变化 | 减少 50%+ | 0分 | — |

> 其他维度（刷练知识点、答题正确率、习题数量、观看课程数量）的评分规则类似，详见评分公式表格图片。

**日报评分示例:**

```
示例1（周报）:

### 2.4.2 🆕 综合评分规则（融合变化与绝对值）

#### 评分示例

**示例 1: 无对比数据的周报**

```
本周使用 2 小时，上周无数据（使用时长 = 0）→ 使用"绝对值"列

- 刷练知识点: 3个 → 查表"绝对值"列 → 2-5个 → 70分

- 观看课程数量: 1节 → 查表"绝对值"列 → 1-2节 → 60分
- 学习目标完成率: 70% → 查表 → 60-80% → 60分

综合评分 = 70×0.25 + 70×0.25 + 85×0.15 + 70×0.15 + 60×0.1 + 60×0.1
         = 17.5 + 17.5 + 12.75 + 10.5 + 6 + 6
         = 70.25 ≈ 70分 → 标签"稳步前进"
```

**示例 2: 有对比数据的周报**

```
本周使用 2 小时，上周使用 1 小时（增加 100%）→ 使用"变化幅度"列

- 观看课程数量: 持平 → 查表"变化幅度"列 → 持平 → 70分
- 学习目标完成率: 70% → 查表 → 60-80% → 60分

综合评分 = 100×0.25 + 85×0.25 + 85×0.15 + 100×0.15 + 70×0.1 + 60×0.1

**展示条件判断逻辑：**

```
是否展示引导卡片 = 
    授权状态 == 未授权 
    AND (
        (首次拒绝授权) 
        OR (
            当前时间 - 引导卡片关闭时间 > 7天 
            AND 有新的学习建议内容
        )
    )
```

**反馈收集:**

| 反馈类型 | 触发方式 | 说明 |
| --- | --- | --- |
| 家长主动正向反馈 | 家长查看推荐且孩子使用有成效 | 权重 = 1.0 |
| 无反馈 | 家长查看但孩子未使用/无成效 | 权重 = 0.5 |
| 家长主动负向反馈 | 家长点击"暂不需要"并勾选原因 | 权重 = 0 |

**多轮反馈叠加:**
- 最新反馈权重占比: 70%
- 历史反馈权重占比: 30%
- 超过 60 天的历史反馈: 权重降至 20%

#### 4.7.6 🆕 推荐间隔策略

**计算公式:**

```
最终间隔 = 基础间隔 × (1 + α×消化系数 + β×反馈系数 + γ×新鲜度系数)
```

**基础推荐间隔:**

| 用户类型 | 关注度 | 基础间隔 |
| --- | --- | --- |
| 新用户（冷启动） | — | 7 天 |
| 老用户 | 深度关注 | 3 天 |
| 老用户 | 中度关注 | 7 天 |
| 老用户 | 轻度关注 | 14 天 |
| 老用户 | 极少关注 | 30 天 |

**调节系数:**

| 系数 | 条件 | 取值 | 效果 |
| --- | --- | --- | --- |
| 消化系数 | 上次推荐使用率/完成率 < 30% | 0.5 | 延长间隔 |
| 消化系数 | 上次推荐使用率/完成率 30%-80% | 0.3 | 小幅延长 |
| 消化系数 | 上次推荐使用率/完成率 ≥ 80% | 0 | 无调整 |
| 反馈系数 | 家长未查看上次推荐 | 0.5 | 延长间隔 |
| 反馈系数 | 家长查看但孩子未使用 | 0.3 | 小幅延长 |
| 反馈系数 | 家长查看且孩子使用 | 0 | 无调整 |
| 反馈系数 | 家长查看且不考虑 | -0.2 | 缩短间隔 |
| 新鲜度系数 | 近 3 次同一对象推荐重合度 ≥ 50% | 0.3 | 延长间隔 |
| 新鲜度系数 | 重合度 < 50% | 0 | 无调整 |
| 新鲜度系数 | 新推荐对象（全量上线 < 30 天） | -0.2 | 缩短间隔 |

### 4.8 推荐算法

#### 4.8.1 APP 推荐得分

| 项 | 公式/说明 |
| --- | --- |
| 总得分 | `S_total = [Σ i=1..4 (S_rule-i × W_rule-i × W_scene-i)] × W_feedback` |
| 含义 | 应用的最终推荐总得分，得分越高优先级越高 |
| 取值范围 | 0-100 |
| S_rule-i | 第 i 个规则的维度得分（i=1 时间节点, i=2 关联应用, i=3 薄弱学科, i=4 核心学霸应用） |
| W_rule-i | 第 i 个规则的权重（0.35, 0.25, 0.20, 0.15） |
| W_scene-i | 不同学情场景下的场景权重 |
| W_feedback | 用户反馈权重（正向=1, 无反馈=0.5, 负向=0） |

#### 4.8.2 PLAN 推荐得分

| 项 | 公式/说明 |
| --- | --- |
| 总得分 | `S_total = [Σ i=1..2 (S_rule-i × P_scene-i)] × W_feedback` |
| 含义 | 计划的最终推荐总得分，得分越高优先级越高 |
| 取值范围 | 0-100 |
| 规则维度 | `i=1` 为时间节点，`i=2` 为薄弱学科 |

#### 4.8.3 MODEL 推荐得分

| 项 | 公式/说明 |
| --- | --- |
| 总得分 | `S_total = [(M_similar × 0.5) + (M_progress × 0.3) + (M_recent × 0.2)] × W_feedback × 100` |
| M_similar | 榜样用户匹配权重，0-1 |
| M_similar 计算 | 年级 0.3 + 学科 0.3 + 机型 0.2 + 城市 0.1 + 使用天数 0.1 |
| M_progress | 成效学科优先级权重，0 或 1 |
| M_progress 规则 | 榜样用户的成效学科与薄弱学科匹配时为 1，不匹配为 0 |
| M_recent | 🆕 榜样用户近期活跃度权重，0-1（⚠️ 原始 PRD 未定义 M_recent 计算方式，需算法侧补充） |

#### 4.8.4 🆕 最终推荐排序与展示

| 步骤 | 说明 |
| --- | --- |
| 1. 分别计算得分 | 对候选 APP、PLAN、MODEL 分别计算各自得分 |
| 2. 乘以类型权重 | final_app_score = app_score × W_type_app |
| 3. 合并排序 | 将所有候选对象按 final_score 降序排列 |
| 4. 去重 | 同一应用/计划不重复出现；同一学科方向最多展示 2 条推荐 |
| 5. 截取展示 | 取 Top 3 推荐结果展示在学习建议模块 |
| 6. 🆕 兜底策略 | 若推荐结果不足 3 条，用"热门应用推荐"补足；若无任何推荐结果，隐藏学习建议模块 |

## 7. M6 微信服务通知

### 7.1 模块目标

通过微信服务通知触达家长，引导家长查看学情报告，提高被动触达和报告查看率。

### 7.2 功能链路

| 步骤 | 说明 | 🆕 补充细节 |
| --- | --- | --- |
| 1 | 报告页提供微信服务通知相关入口或引导 | 首次进入报告页时展示订阅引导弹窗 |
| 2 | 用户触发订阅/开关设置 | 调用微信小程序订阅消息 API |
| 3 | 微信侧接收服务通知消息 | 服务端在报告生成后触发消息推送 |
| 4 | 用户点击微信通知 | 跳转到小程序学情报告页 |
| 5 | 跳转回学情报告页面 | 小程序内展示对应日报/周报 |

### 7.3 🆕 通知触发规则

| 项 | 规则 |
| --- | --- |
| 触发场景 | 日报生成后、周报生成后 |
| 发送时间 | 日报: 次日 8:00-9:00；周报: 周一 8:00-9:00 |
| 发送频次 | 每份报告最多发送 1 次通知 |
| 前提条件 | 用户已订阅微信服务通知 |
| 通知模板 | ⚠️ 需申请微信订阅消息模板，模板内容需微信审核 |

> 📐 **补充说明:** 原始 PRD 微信服务通知章节仅有原型图，文字需求极少。此处补充通知触发规则和订阅流程。

## 10. 灰度策略

在依赖应用升级的前提下分批灰度:

| 批次 | 用户范围 | 灰度比例 |
| --- | --- | --- |
| 第一批 | 活跃用户，周使用 ≥ 3 天 | 20% |
| 第二批 | 活跃用户，周使用 ≥ 1 天 | 20% |
| 第三批 | 活跃用户，周使用 ≥ 0 天 | 20% |

灰度观察周期为 3 周。若无负面反馈且数据稳定，再放开全量。

🆕 **灰度观察指标:**

| 指标 | 观察标准 | 异常阈值 |
| --- | --- | --- |
| 报告页崩溃率 | 灰度组 vs 对照组 | 灰度组崩溃率高于对照组 0.5% 以上 |
| 报告加载耗时 | P95 加载时间 | 超过 3 秒 |
| 有效报告查看率 | 灰度组 vs 对照组 | 灰度组低于对照组 5% 以上 |
| 用户投诉率 | VOC 相关投诉 | 出现批量相似投诉 |

🆕 **灰度回滚条件:**

满足以下任一条件时触发回滚讨论:
1. 灰度组崩溃率显著高于对照组
2. 出现 P0 级功能缺陷
3. 用户投诉集中且影响面广
4. 核心指标（查看率、推荐点击率）显著下降

🆕 **灰度模块拆分建议:**

| 模块 | 灰度批次 | 说明 |
| --- | --- | --- |
| M1 学情总结 + M2 家长鼓励 | 第一批 | 核心体验，优先验证 |
| M3 学习成果/建议 | 第一批 | 核心价值模块，需尽早验证推荐效果 |
| M4 本周/今日任务 | 第二批 | 依赖任务数据源就绪 |
| M5 公域分享 | 第二批 | 依赖分享素材生成服务就绪 |
| M6 微信服务通知 | 第二批 | 依赖微信订阅消息模板审核 |
| M7 应用跳转优化 | 第一批 | 改动较小，可随核心模块一起上线 |
| M5-2 企微私域分享 | 第三批或独立排期 | 方案待确认，暂不评审 |
