| 场景 | 规则 |

### 2.3 模块展示优先级

【补充】报告页模块建议按用户理解路径排序，先结论、再证据、再行动:

| 优先级 | 模块 | 展示原则 |

| P1 | 分享入口 | 版本支持时展示，分享引导气泡需满足触发条件 |
| P2 | 应用跳转 | 应用使用列表中存在可跳转应用时开放 |
| P2 | 微信服务通知入口 | 根据订阅状态和触达策略展示 |

### 2.4 数据不足与异常兜底

| 场景 | 产品规则 |
| --- | --- |
| 首次生成报告且无历史数据 | 原文: 不展示学情总结标签 |
| 学习数据不足但可生成报告 | 【补充】报告不应空白，应展示基础使用概况和轻量建议，例如“本周期学习数据较少，建议保持稳定使用后查看更完整分析” |
| 关键数据计算失败 | 【补充】隐藏依赖该数据的模块，不展示错误值、空卡片或异常分数 |
| 推荐结果为空 | 【补充】学习建议模块可展示通用建议或隐藏推荐卡片，避免出现“暂无推荐”造成负向感知 |
| 图片、分享素材生成失败 | 【补充】提示用户稍后重试，已生成的报告正文不受影响 |
| 跨端消息发送失败 | 【补充】家长鼓励需给出发送失败状态，允许重试 |

### 2.5 授权与隐私规则

| 场景 | 产品规则 |
| --- | --- |
| 学习建议开启 | 原文: 需同意《科大讯飞AI学习机用户学习报告信息授权》 |

| 授权用途 | 原文: 用于学习报告生成与展示 |
| 用户不同意授权 | 【补充】不展示个性化学习建议和推荐解释，可展示授权引导或隐藏该模块 |

### 2.6 内容口径与表达原则

| 原则 | 说明 |
| --- | --- |
| 正向表达 | 学情报告面向家长，应避免制造焦虑，薄弱点表达需给出可执行建议 |
| 数据可解释 | 涉及进步、薄弱、推荐时应尽量说明依据，例如使用时长、正确率、完成量、错题次数 |
| 低数据不强判定 | 数据不足时不输出强结论，不给出“表现差”等负向标签 |
| 推荐要有理由 | 推荐应用/计划时应说明推荐原因，便于家长理解和点击 |
| 【新增】儿童隐私保护 | 分享素材默认避免暴露过多个人敏感信息，头像、昵称、学校、城市等信息需遵循授权范围 |

## 4. M1 学情报告基础与学情总结

### 4.1 模块目标

在日报/周报详情页提供“学情总结”能力，用总结文案、表现标签、使用时长、应用使用情况和行动建议帮助家长快速理解孩子当前周期的学习表现。

### 4.2 入口与适用范围

| 项 | 规则 |
| --- | --- |
| 适用版本 | App 版本 ≥ V4.0.0 |
| 低版本策略 | 原文: 低版本无此模块展示，不做兼容处理 |
| 报告范围 | 日报、周报 |
| 入口 1 | 学习 tab 页点击【日报周报】按钮进入报告页 |
| 入口 2 | 点击学情报告消息进入报告页 |
| 【补充】入口 3 | 从微信服务通知、push、分享回流进入报告页时，仍应复用同一报告详情页结构 |

### 4.3 页面结构

| 区域 | 内容 | 要求 |
| --- | --- | --- |
| 顶部信息 | 孩子头像、昵称、报告类型、日期范围 | 展示当前查看的是日报还是周报 |
| 本周/今日总结 | 总结文案、进步点、薄弱点、家长行动建议 | 结论先行，避免堆叠指标 |
| 使用时长 | 总学习时长、环比变化、日期趋势 | 支持日报/周报不同周期口径 |
| 应用使用情况 | 自研应用、三方应用、重点应用使用时长 | 可点击应用进入 M7 应用足迹 |
| 学情表现标签 | 标签文字、标签视觉、综合评分区间 | 首次无历史数据时不展示标签 |
| 鼓励入口 | 家长鼓励按钮文案 | 与 M2 家长鼓励打通 |
| 后续行动 | 学习成果、学习建议、任务、分享 | 与 M3/M4/M5 联动 |

### 4.4 生成与展示规则

| 场景 | 规则 |
| --- | --- |
| 日报生成 | 原文: 当日 24:00 后生成并展示“学情总结”标签，覆盖当日 00:00-24:00 学习数据 |
| 周报生成 | 原文: 每周日 24:00 后生成并展示“学情总结”标签，覆盖周一 00:00-周日 24:00 学习数据 |
| 首次无历史数据 | 原文: 用户首次生成学情报告且无历史数据，不展示学情总结标签 |
| 学期内动态维护 | 原文: 标签映射评分规则按学期内数据动态维护 |
| 【补充】报告已生成后进入 | 默认展示已生成报告，不要求家长等待实时计算 |
| 【待确认】报告生成后是否随当日新数据刷新 | 需确认日报/周报生成后是否冻结版本，或允许重新计算 |

## 5. M2 家长鼓励

### 5.1 模块目标

家长在 App 报告页向孩子发送鼓励，孩子在学习机端收到鼓励并回复表情，家长在 App 端看到孩子回复，形成跨端互动闭环。

### 5.2 用户流程

| 步骤 | 端 | 行为 | 结果 |
| --- | --- | --- | --- |
| 1 | App | 家长在报告页点击鼓励入口或鼓励按钮 | 进入鼓励发送流程 |
| 2 | App | 家长确认发送鼓励 | 鼓励消息发送到学习机 |
| 3 | 学习机 | 孩子收到鼓励消息 | 展示弹窗或蒙层 |
| 4 | 学习机 | 孩子点击消息并选择 emoji 回复 | 回复结果回传 |
| 5 | App | 家长再次查看报告或消息 | 看到孩子回复表情或回复状态 |

### 5.3 发送规则

| 规则项 | 说明 |
| --- | --- |
| 文案来源 | 鼓励文案来自 M1 学情标签映射 |
| 发送对象 | 当前报告对应孩子绑定的学习机 |

### 6.8 推荐算法口径

| 推荐类型 | 产品口径 |
| --- | --- |
| APP | 应用最终推荐总得分 `S_total = [Σ i=1..4 (S_rule-i × W_rule-i × W_scene-i)] × W_feedback`，范围 0-100，得分越高优先级越高 |
| PLAN | 计划最终推荐总得分 `S_total = [Σ i=1..2 (S_rule-i × P_scene-i)] × W_feedback`，其中规则维度包括时间节点和薄弱学科 |
| MODEL | 榜样模型得分 `S_total = [(M_similar × 0.5) + (M_progress × 0.3) + (M_recent × 0.2)] × W_feedback × 100` |
| MODEL 相似度 | 年级 0.3 + 学科 0.3 + 机型 0.2 + 城市 0.1 + 使用天数 0.1 |
| MODEL 成效学科 | 榜样用户的成效学科与薄弱学科匹配时为 1，不匹配为 0 |

## 12. 灰度策略

### 12.1 灰度批次

在依赖应用升级的前提下分批灰度:

| 批次 | 用户范围 | 灰度比例 |
| --- | --- | --- |
| 第一批 | 活跃用户，周使用 ≥ 3 天 | 20% |
| 第二批 | 活跃用户，周使用 ≥ 1 天 | 20% |
| 第三批 | 活跃用户，周使用 ≥ 0 天 | 20% |

灰度观察周期共 3 周。若无负面反馈且数据稳定，再放开全量。

### 12.2 灰度观察指标

| 指标 | 说明 |
| --- | --- |
| 报告查看率 | 观察是否较旧版提升 |
| 推荐卡片点击率 | 观察学习建议是否带动应用/计划 |
| 分享入口点击率和发布率 | 观察分享能力接受度 |
| 微信通知送达率和点击率 | 观察被动触达效果 |
| 负反馈 | 客服反馈、用户投诉、取消订阅、页面退出率异常 |
| 【补充】稳定性 | 页面加载失败率、素材生成失败率、跨端鼓励发送失败率 |

### 12.3 灰度暂停条件

【新增】出现以下任一情况建议暂停扩大灰度:

| 条件 | 说明 |
| --- | --- |
| 数据异常 | 关键指标无法统计，或口径明显错误 |
| 用户负反馈集中 | 与隐私、焦虑表达、推荐不准、通知打扰相关的反馈集中出现 |
| 核心链路异常 | 报告无法查看、分享无法生成、通知无法跳转、鼓励消息大量失败 |
| 合规风险 | 授权、分享内容或儿童信息展示存在风险 |
